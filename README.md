# coverage-radar

**Which institutional investors should the sales team call this quarter — and does a model's list beat "call the biggest ones first"?**

A sales-insights tool for an asset manager's client coverage team, built on real, public holdings data. It ranks institutions by their likelihood of putting new money into the house's ETFs next quarter, explains each pick in plain words, writes a short call-prep briefing whose numbers are checked against the data, and shows it all in an R Shiny app for sales team leaders and salespeople.

> **Status:** in development. Every number in this README comes from runs of the code in this repository. Nothing is an estimate.

---

## The users and the problem

| User | Decision | What coverage-radar gives them |
|---|---|---|
| **Sales team leader** (primary) | Which prospects and clients the team covers this quarter, with a fixed number of calls | A ranked call list per territory, with reasons and expected new money |
| Salesperson | How to prepare for a call | A one-paragraph briefing: what the institution holds, what changed, why it is on the list |
| Head of sales | Where the opportunity sits | Overview by segment and territory; how well past lists performed |

**Status quo baseline:** "call the largest institutions first". Every model has to beat it, or it is not worth building.

**North-star metric:** institutions on the list that actually add money to the house's ETFs in the next quarter, **per 100 calls**, at a fixed call capacity (e.g. 20 salespeople × 10 calls = 200 per quarter).

**Guardrails:** estimated new money captured by the list (not just the count of hits), quarter-to-quarter list stability (salespeople should not get a completely new list every time), coverage of existing large clients, and 0 unsupported numbers in briefings.

## Data

| Source | Content | Access |
|---|---|---|
| SEC Form 13F data sets | Quarterly holdings of US institutional investment managers with at least $100M in 13(f) securities: issuer, CUSIP, class, value, shares; filer name and address | Free bulk ZIP files from the SEC, from 2013 Q2 |

Institutions file Form 13F within 45 days of quarter end. ETFs are 13(f) securities, so every filer's ETF holdings, including the house's ETFs and competitors', are visible quarter by quarter.

**The house** is a configurable ETF family (`config/house.yaml`: issuer-name patterns and CUSIP list). The default is a mid-sized family. The project describes behaviour visible in public filings and makes no claims about any firm's actual clients.

**Data pitfalls handled in code** (and documented in `docs/data_note.md`):
- amendments: restatements replace the original filing; new-holdings amendments add to it;
- grouping by period of report, not by file (recent SEC files span filing months, not quarters);
- units of `VALUE` changed over time (thousands vs dollars); checked against shares × price;
- option rows (`PUTCALL`) excluded;
- **share changes, not value changes**: a position that grew because prices rose is not new money. Net new money = change in shares × current price;
- filers appearing and disappearing between quarters.

## How it works

```
13F ZIPs ─► load + clean (DuckDB/Parquet) ─► filer-quarter panel
                                                 │
                     features: size, ETF share, competitor holdings,
                     momentum, turnover, territory, filer type
                                                 │
                     target: adds ≥ $X net new money to house ETFs next quarter
                                                 │
            models (baselines → logistic → LightGBM) ─► ranked list + reasons
                                                 │
            briefing generator (LLM, numbers checked) ─► R Shiny app
```

**Validation:** out-of-time only. Models are trained on quarters up to t and tested on later quarters they never saw. Each test quarter mimics a real decision: the list is built with filings available at that time.

## What the user gets

- **Call list:** top-K institutions per territory (state from the filing address), with probability, expected new money, and the three main reasons in plain words (e.g. "holds $40M in competitor bond ETFs", "ETF share up from 12% to 19% in two quarters", "no house ETFs yet").
- **Client profile:** holdings history in house vs competitor ETFs, last quarter's changes, briefing.
- **Overview:** opportunity by segment and territory; backtest of how each past quarter's list performed.
- **Call-prep briefing:** one paragraph per institution, generated by an LLM from a fact sheet. Every number in the text is checked against the data; a briefing with an unsupported number is regenerated or replaced with a template.

## What it measures

| Area | Metric |
|---|---|
| Ranking | Hits per 100 calls at capacity K; estimated new money captured at K; lift over "biggest first"; PR-AUC |
| Calibration | Brier score; predicted vs actual hit rate by decile |
| Stability | Overlap of consecutive quarterly lists |
| Briefings | Unsupported-number rate (target 0); share of briefings needing the template fallback; tokens and cost per briefing |
| Engineering | Pipeline runtime from raw ZIPs to app data |

## LLM use, and its limits

- The LLM writes text; it never computes numbers. Numbers come from the fact sheet and are checked by code.
- Backend-agnostic client: Azure OpenAI or any OpenAI-compatible endpoint; a small local model as a fallback. Model name, version and date are stored with every briefing.
- Only public filing data goes into prompts.

## Quickstart

```bash
pip install -e ".[dev]"
# download 13F data set ZIPs from the SEC into data/raw/
make data        # load, clean, panel
make train       # baselines and models, out-of-time
make evaluate    # tables and plots for this README
make briefings   # briefings for the latest call list, with number checks
make app         # R Shiny app on localhost
pytest
```

## Roadmap

The MVP answers one question: who to call. Planned extensions, each with its own measured result:

1. **Retention early warning:** which existing holders are likely to reduce or sell house ETFs next quarter; same panel, opposite target.
2. **Next best product:** classify ETFs into asset classes (LLM classifier validated on a hand-labelled sample), then recommend which house product to pitch to each institution; evaluated on next-quarter purchases.
3. **Firm enrichment:** link filers to SEC Form ADV (adviser type, client types, total assets under management) for better segmentation.
4. **Ask-your-data assistant:** natural-language questions over the panel answered with SQL, evaluated on a fixed set of questions with known answers (execution accuracy), with read-only access.
5. **Forward test:** predictions frozen in January 2027 for Q4 2026, scored when Q4 filings arrive in mid-February 2027.
6. **Deployment:** Docker, a Kubernetes manifest (AKS-ready), quarterly refresh and monitoring of list performance; a Power BI version of the overview page.

## Limitations

- 13F covers US-listed securities held by large US-reporting institutions. It does not show mutual funds, UCITS, mandates or European clients; methods transfer, the client base does not.
- Holdings are reported quarterly with up to 45 days' delay, so the list is built on data that is up to four months old, as a real team would face.
- Net new money is estimated from share changes and quarter-end prices, not observed flows.
- A filer is an investment manager, not the end client; the same manager may act for many clients.
- Educational project; it does not reproduce any firm's sales methodology.
